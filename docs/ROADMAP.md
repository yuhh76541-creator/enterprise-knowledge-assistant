# 分阶段开发路线

## M0：基础框架（本次）

- [x] Vue + TypeScript 工作台与 API 客户端
- [x] FastAPI 配置、健康检查与 SQLite 初始化
- [x] 知识空间创建、列表、详情与持久化
- [x] 输入校验、重复名称处理、无密钥泄露的状态响应
- [x] 后端测试、前端构建与 Windows 启停脚本

## M1：文档入库

- [ ] 知识空间内上传 TXT/Markdown，文件大小和类型限制
- [ ] 上传文件采用生成的存储名，防止路径穿越
- [ ] 文档元数据、处理状态、分段及失败重试
- [ ] SQLite 版本迁移与文档删除流程
- [ ] 再扩展 PDF/DOCX，验证中文提取与异常文档处理

验收：公开示例文件可上传、分段、查看与删除；重启后数据保留。

## M2：检索与引用

- [ ] 选择 embedding 方案，明确何时会把文档发送给外部服务
- [ ] 文档分段、向量索引及知识空间隔离
- [ ] 检索接口返回来源文件、位置和片段
- [ ] 构建固定问题集，记录 Recall@K 与耗时，不预填结果

验收：使用固定问题集验证相关片段，记录真实检索结果。

## M3：远程模型与 RAG 问答

- [ ] 实现远程模型客户端（优先 DeepSeek），有连接和整体超时
- [ ] 基于检索片段生成回答，未检索到依据时明确说明
- [ ] 返回可核验的引用，区分引用内容与模型生成内容
- [ ] 防范文档中的指令覆盖系统规则；不允许文档自动触发工具操作
- [ ] 保存会话、调用成本及失败状态，实际评测答案质量

## M4：业务助手与访问控制

- [ ] IT 故障资料查询与排查步骤参考
- [ ] 用户登录、角色权限、知识空间访问检查与审计记录
- [ ] 脱敏、备份、限流、部署及真实环境验证

“完成”必须有代码、测试和运行记录。简历可先写“搭建项目基础框架”，不能提前写“完成企业级 RAG 平台”或未经测量的性能提升。
